# phone-control

**一句话：让 AI 替你读 Android 手机上的内容、并真的上手操作。**

它做两件事，是一个闭环：

- **读** —— 把手机屏幕上的内容变成 AI 能读的文字：当前这一屏、以及连续滚动翻出来的长内容（聊天记录、长列表、长文章）。
- **操作** —— 按读到的位置点按、输入、翻页，点完再读一遍确认真的生效了。

手机屏幕本身是像素，直接交给 AI 也能看，但没有"导出成带坐标的文字"来得准和省。所以默认走文字通道，
截图视觉只作兜底。

可用在 DeepSeek Harness（dsh）、WorkBuddy、Claude Code、Codex、Cursor 等支持 SKILL.md 的编程助手上（MIT 开源）。

## 能力

| 能力 | 说明 |
|---|---|
| 读当前屏幕 | 一屏完整数据 42KB，压到约 2.5KB 再读；一次约 0.8 秒 |
| 读长内容 | 连续滚动翻页，自动去重（交界处不重复）、自动剥掉吸顶/吸底栏、滑到底自动停 |
| 打字 | 英文/数字直接输；**中文也能输**（需一个不装 App、不改输入法的注入小程序，见「依赖」） |
| 复杂手势 | 长按拖拽、双指缩放（拖滑块、拖文件、地图缩放这类，原生命令做不了） |
| 只认当前这一屏 | 先花几字节确认手机正显示的是目标 App，避免在错误页面上白试 |
| 点完会等 | 每 0.3 秒看一眼屏幕，等到**界面真的变了**才往下走，不靠"等几秒"撞运气 |
| 坐标算好了 | 要点的位置直接给坐标，不用自己心算中点 |
| 读不出来有兜底 | 文字通道实在读不出内容时，从画面把位置算出来 |
| 提速是可选的 | 手机上没装那个小程序时自动用回原通道，只是慢，功能一点不少 |
| 提交前会核对 | 提交 / 支付 / 删除这类**点了退不回来**的操作：动手前回读一遍，动手后再核对一遍，逐项跟你确认才动 |
| 用久了会变聪明 | 踩过的坑会记成经验，下次自动绕开；记下来的经验还会定期回看有没有过期 |
| 装好能自检 | 跑一条命令就给结论：能不能开始用（0 能用 / 1 能用但有提醒 / 2 等你拍板 / 3 不能用） |
| 能按自己机器调 | adb 路径、默认用哪台手机、超时多久、多久看一眼，都能改；不改也能跑 |

## 安装

挑一种顺手的装法。**不管哪种，最后都要整个目录放进助手的 skills 子目录**（目录名保持 `phone-control`）。

仓库：`github.com/OTH-C3/phone-control`（公开，MIT）

### 装到 DeepSeek Harness（dsh）

下完仓库后跑一条命令：

```bash
cd phone-control
bash scripts/install-dsh.sh
```

它会自己找到 dsh 的目录、装好、检查有没有 adb，最后告诉你装到哪了。
dsh 装在别的位置就把路径当参数传进去：`bash scripts/install-dsh.sh /path/to/.dsh`。

装完在 dsh 里直接说「帮我看看手机上开着什么」就会用它。

想确认装没装上，看 `~/.dsh/skills/phone-control/SKILL.md` 在不在即可 —— dsh 启动时扫这个目录。
（`dsh --profile web --dump-config` 打印的是 profile 的插件配置，不含技能列表，别拿它判断。）

> 已有 `scripts/config.env` 不会被覆盖 —— 那是你自己机器的配置（adb 路径、设备号、超时），重装也保留。

dsh 除了 `~/.dsh/skills/`，也读 `~/.agents/skills/`（通用目录，好几个工具共用）。
想把 skill 在多个工具间共享就放 `~/.agents/skills/`；只给 dsh 用就放 `~/.dsh/skills/`（优先级更高，同名时以它为准）。

### 其余助手的装法

**方式一：git clone（有 git 的机器）**

```bash
git clone https://github.com/OTH-C3/phone-control.git
mkdir -p ~/.workbuddy/skills
cp -r phone-control ~/.workbuddy/skills/
```

**方式二：下载 zip（不想装 git）**

GitHub 页面上 `Code → Download ZIP`，解压后把 `phone-control/` 整个拷进 skills 目录。

### 依赖

- **Android SDK Platform Tools**（`adb`）。满足任一即可，脚本按序自动探测：`--adb` 参数、`config.env` 的 `ADB_PATH`、`$ANDROID_HOME/platform-tools/adb`、`~/Android/Sdk/platform-tools/adb`、`adb` 在 PATH、Windows 下 `~/AppData/Local/Android/Sdk/platform-tools/adb.exe`。
- **Python 3**，只用标准库。
- **Pillow**：仅兜底通道 `scripts/pixels.py` 需要（`pip install Pillow`）。不装不影响主链路。
- **要发中文，用仓库里自带的 `bin/yadb`**：系统自带的 `adb shell input text` **发不了中文**，
  这是它本身的限制。本仓库**已内置**这个小工具，**不用另外下载**：
  使用时它会推到手机上、用 `app_process` 跑起来注入文本，**不装 App、也不用改输入法**。
  用法见 `references/facts.md` 的 **F27**。
  它是 LGPL-3.0 的第三方程序，来源与许可写在 `NOTICE.md`；不信任可以删掉，
  只会失去中文输入，**读屏、点按、滚动读取都不受影响**。
- 只读屏幕、只输英文数字的话，`bin/` 整个都不需要。

### 装完先验证一次

```bash
cd phone-control
python3 scripts/check_env.py
```

输出会列出 adb 版本、设备台数及各自状态、落盘目录是否可写、Pillow 有没有装，最后一行给结论。**退出码就是结论**：

| 退出码 | 意思 | 下一步 |
|---|---|---|
| `0` | 可用 | 直接开始 |
| `1` | 可用，但有提醒 | 能用，看输出里 `[提醒]` 那几行 |
| `2` | 可用，等你拍板 | 看 `[待定]`，多半是多设备没指定 serial |
| `3` | 不可用 | 看 `[不可用]` 那几行，先解决再开始 |

确认后再跑一次主通道：

```bash
python3 scripts/probe.py --focus-only
```

打印出「设备 / 焦点 / 栈顶」三行，焦点是目标包名，链路就通了。焦点显示 `null` 或 `NotificationShade` 说明焦点被系统层/通知栏抢走，先切回目标 App。

## 怎么用

### 怎么跟它说话

装好之后直接用大白话下指令就行，下面这些都是能识别的：

读内容类：

- 「帮我看看这条聊天记录」
- 「把这段话读出来」
- 「翻上去看看更早的消息」
- 「把这个列表从头读一遍」
- 「看看我现在手机上开着什么」

操作类：

- 「帮我操作一下手机」
- 「帮我点一下这个按钮」
- 「点开『下一步』，等它跳到下一页」
- 「填一下这个表单：姓名张三，选上『我已阅读』」
- 「这个按钮点不动，帮我试试」
- 「帮我签到 / 打卡 / 提交，提交前先跟我说一声」

说人话就能触发，**不用记住任何命令或术语**。`dump`、`bounds`、`scroll_read` 这些是内部实现，
你说了也没用，它自己知道。

**它不管的**：写 Android 代码、iOS。

### 一次典型的操作长什么样

**操作**：看清楚 → 点下去 → 等界面真的变了 → 再读一遍核对。

最后那步"等"是有讲究的：点完就接着干下一步，很容易点到**下一屏的元素**上，
表现是"我点了提交，结果点到了下一步"，事后才发现问题。所以它不靠"等 1 秒"，而是**轮询到界面真的变了为止**。

**读长内容**：滑一屏 → 等它停稳 → 读一屏 → 和上一屏接起来（去掉交界处重复的部分）→ 一直滑到没有新内容为止。

长内容不能只读当前一屏，也不能靠固定间隔一顿快滑——快滑会读到还没停稳的中间状态，
位置是乱的。所以每滑一次都等到界面真正稳定才读，接起来时去掉重叠，滑不动了就说明到底了。

## 命令一览

```bash
# 先：装完/换机器先跑这个，退出码 0/1/2/3 直接给结论
python3 scripts/check_env.py

# 看：焦点 + 界面元素（默认全输出）
python3 scripts/probe.py
python3 scripts/probe.py --focus-only   只报设备/焦点/栈顶，不导出整屏
python3 scripts/probe.py --limit N      最多打印 N 条元素
python3 scripts/probe.py --quiet        只要元素行，不要头部（做基准快照时用）

# 读长内容：滚动翻页 + 去重 + 拼接
python3 scripts/scroll_read.py --max-screens 30 --out chat.txt
python3 scripts/scroll_read.py --dir up --max-screens 30 --out chat.txt   往前读（更早/更上面的内容）
python3 scripts/scroll_read.py --stop-text "已经是底部"                    读到某句话就停

# 等：替代固定 sleep
python3 scripts/wait_ui.py              界面一变就返回
python3 scripts/wait_ui.py -t "关键词"   等某个文本出现
python3 scripts/wait_ui.py -d "提交中"    等某个文本消失
python3 scripts/wait_ui.py --timeout 8   改超时（默认 5s）

# 兜底：实在读不出内容时，从画面把位置算出来（不猜内容）
python3 scripts/pixels.py shot.png --rows   内容行段，找选项/输入框在第几行
python3 scripts/pixels.py shot.png --dots   蓝/红/绿/青绿色块，找选中态、状态标记
```

操作直接用原生 adb，没有封装层：

```bash
adb shell input tap x y            点击（坐标取 probe 输出的 bounds 中心）
adb shell input swipe x1 y1 x2 y2 ms   滑动 / 拖拽
adb shell input text "xxx"          输入（走输入子系统，绕开输入法）
adb shell input keyevent 4          收键盘 / 返回
```

`probe.py` 输出长这样（每行 = 屏幕上一个元素）：

```
下一步 @ (540,1180)  [300,1150][780,1210]
用户协议 @ (287,1136)  [120,1096][454,1177]
```

左边是文字，中间是**已经算好的点击坐标**，右边是可点范围。

## 两条纪律

1. **动手前先看清楚再点**，别凭印象点。
2. **点完不要靠"等固定几秒"再操作** —— 界面动画还没落定，那一一下可能落到**下一屏的元素**上，
   造成静默错误（点了 A 记成 B，事后才发现）。要用 `wait_ui.py` 等界面真的变了。

**顶部和底部都会吞点击**：状态栏、标题栏、吸底按钮区域（1080x2400 上 y≈200 约 8% 高度处 tap 无反应）。点不动时换个 y 值试它下方的可点区域，别对着同一坐标反复点。

**坐标一律取当前屏幕的实际输出**，不要沿用别的手机或旧记录里的数值——分辨率不一样全都漂。

**滚动过的页面上，坐标不能整份照抄**：列表滚动后可能混进已滚走的残留元素，它们的位置数据是错的，
照它点会点到**别的条目**上。稳妥做法是先滑回列表顶部再看一次。工具已自动剔除这类残留并提示。

提交 / 支付 / 删除这类**退不回来的操作**还有一条：动手前先把屏幕上要提交的那几项读一遍跟你确认，
动手之后再读一遍核对，对不上就停下来，别直接交。

## 设计哲学

### 三条设计原则

- **能省则省，按代价分档。** 读屏幕有四种代价不同的办法（几字节确认焦点在不在 → 2.5KB 的界面小表 →
  从画面算位置 → 把整张图直接看一遍）。永远按代价从低往高走，不跳级。
- **工具宁少不多。** 每个小工具只干一件事，真正的动作直接调 `adb`，中间不套封装。
  想加新的之前先问：现有的加上 `adb` 本身能不能解决？每加一个就多一处职责重叠。
- **踩过的坑要留下来。** 不是改完就算了，踩坑当场记成一条能复用经验，写完立刻用真机验一遍；
  过期了别删、改标失效——"从哪版开始变了"比删掉有用。

## 与同类方案的取舍

| 方案 | 取舍 |
|---|---|
| 直接截图让 AI 看 | 把整张图丢过去，费得多，还得自己估坐标。只在读不出内容、且非看画面不可时才用 |
| uiautomator2 / 无障碍服务 | 要往应用进程或系统服务里插手，还得额外装东西；本工具只调 `adb`，什么都不用装 |
| 每步写一个定制脚本 | 换个 App 就全废。本工具只做通用机制，某个 App 特有的规律单独记、不写死在流程里 |
| 多开几个 AI 并行操作多台手机 | 本工具自己就能并发：同时接几台也不打架，多设备时你指定用哪台就是 |

## 目录结构

```
SKILL.md        完整说明：怎么读、怎么操作、遇到情况怎么选、退不回来的操作怎么核对
scripts/        几个各管一件事的小工具（看当前屏 / 读长内容 / 等界面 / 算位置）+ 环境自检 + dsh 一键安装
templates/      配置模板，首次运行会自动生成一份，一般不碰
references/     补充资料：踩坑速查表、其他连法、经验库（已有 2 条真实样本，会持续长）
docs/           改造方案与实测记录，想自己改这套工具时看
bin/            中文输入用的小工具（已内置，不用另外下载）；只要发中文才需要
.claude-plugin/ 插件清单，让 dsh / Claude Code 把它当插件识别
NOTICE.md       第三方组件声明（bin/ 里那个工具的来源与许可）
```

装的时候按前面「方式三」把文件按同样的层级放好就行，缺 `scripts/` 里的东西会跑不起来。`SKILL.md` 是
完整说明，想看细节（各种边界情况怎么应对）读它就够。

`bin/` 是可选的：删掉它只会失去「发中文」，读屏、点按、滚动读取、等待都照常。

配置想改就改 `scripts/config.env`（首次运行自动生成），里面每一行都有中文注释。

## 已知边界（说实话）

- **读当前屏、读长内容都已实测**：滚动翻页、交界去重、吸顶剥离、到底判定，都在多屏页面上跑过。
- **多数 App 的文字都读得到**：原生控件、**网页（WebView）正文**、系统弹窗都在内。实测过设置、短信、
  联系人、拨号、日历、时钟、文件管理器、相册、桌面、第三方 App 共 10+ 个界面。
- **真正读不到的只有"本来就没有文字的画面"**：画布、游戏、视频帧、纯图片列表 —— 这类才需要走兜底。
- **两种"看着像读不到"其实不是**：一是焦点被系统弹窗抢走（读到的是权限框，不是目标 App），
  二是页面还没加载完就读（只回标题栏这类外壳，等一下再读就有正文）。都已在文档里给出判别方法。
- **自检的四档结论都实测过**：没连上手机（不可用）、配置缺失（能用但有提醒）、一切正常（能用）都跑过；
  「多台手机待你指定」那档在只有一台手机的环境下没触发过，判断逻辑是同一套。
- **具体某个 App 的坑攒下 2 条（系统设置主页、微信聊天页）** —— 通用的滚动读取、坐标、输入机制都已实机实测，
  但每个 App 特有的刁钻之处要实跑才写得到，会随着使用逐渐变多。
- **中文输入已在真机实测通过**：搜索联系人、读聊天记录、输入并发送中文的完整链路都跑过。
  做法是用 **yadb** 这类小程序，**不装 App、不改输入法**（见「依赖」）。
- **「画布类画面的兜底」只有机制、没有真实案例** —— 还没遇到真需要靠兜底才读得出的界面。
- **需要 App 内部原始数据**（而不是屏幕上看得见的）的情况，基本拿不到，老老实实从屏幕读。
- **只支持 Android。** iOS 和电脑不在范围内。
- **「等某个东西消失」这条分支的成功路径还没实测**（跟它共用同一套判断代码，风险低但缺实证）：
  跑过的只有「一开始就还没出现，立即返回」和「一直不消失，超时退出」这两条。
- **无线网络调试没实测过**，只是方案的记录都在；要用你得先自己让手机和电脑连上调试。
- **只用 USB 线连手机是最稳的**，无线那套没人给你验过。
- **dsh 侧验证到「能被识别、能装上」为止**：安装脚本跑通、清单文件按 dsh 的实际读取格式写、
  助手侧确认能读到技能列表；**没有在真实对话里跑完一整轮手机操作**。装好后请自己试一句
  「帮我看看手机上开着什么」，读不到就把 `SKILL.md` 头部那几行检查一遍。
