# 经验生长手册

**前提：经验不是写文档，是让下一个任务少踩一次坑。**
本手册解决四件事：**什么时候写、什么算合格、写完怎么验、过期了怎么办。**

---

## 1. 经验分三层，先想清楚写哪层

| 层 | 内容 | 放哪 | 换一个 App 还成立吗 |
|---|---|---|---|
| **L1 通用纪律** | 焦点确认、轮询替代 sleep、不可逆先核对 | 已经在 `SKILL.md` 里 | 恒成立 |
| **L2 通道/机制层** | "这类页面 dump 读得到"、"WebView 不走 DOM" | 本文件、channels.md | 换 App 也成立 |
| **L3 App 页面层** | 某个包某个页面的交互规律、坑 | `app-profiles/<pkg>--<page>.md` | 只在这一个 App |

**第一问：换个 App 还成立吗？成立就别写进 app-profile，它属于 L1/L2。**
app-profile 里塞通用纪律，等于把通用知识复制了 N 份，改一处漏 N 份。

### L3 内容再分三类，一个文件里分开写

落到某个 App 某个页面的经验，写的时候**必须分开成三块**，别混成一段流水账：

| 类别 | 回答什么 | 判定 |
|---|---|---|
| **① 平台特征** | 这页天生是什么样（原生/WebView、吸顶吸底、点完自不自跳） | 换台手机也一样，属页面固有属性 |
| **② 有效模式** | 对这一页该怎么做才对（用哪个文本当验证锚点、该用 `-t` 还是 `-d`） | 写下来就能立刻照做 |
| **③ 已知陷阱** | 踩过的坑：现象 → 原因 → 做法 | **必须有真实踩坑记录，没踩过别编** |

分三类是为了让读的人能跳读：想"这页什么结构"只看①，想"我该点完怎么验"只看②，
想"上次在哪儿翻车"只看③。混在一起三段都得读，还分不清哪条是自己要的。

## 2. 什么时候该写（触发条件，别靠自觉）

出现下面任一条，**当场就要走一遍本手册**，不要"等有空再补"：

1. **踩坑了** —— 点了没反应、答错/选错、焦点跑偏、数值算错、界面没按预期变；
2. **发现一个新交互规律** —— 点完自动跳下一页 / 原地刷新 / 要手动点「下一步」/ 会弹确认框；
3. **发现某类页面 dump 读不到** —— 需要换通道或用像素兜底；
4. **通道选型结论** —— 这类页面是 WebView，走 dump 不走 DOM、不走 CDP；
5. **撞见不可逆动作** —— 提交、支付、删除、签到，且确认框/按钮位置有坑。

> 第 1 条最有价值。**每次操作出问题的第一反应应该是"这条坑值不值得存"，而不是"先修完再说"。**

## 3. 什么才算合格经验（三问，全过才写）

写完前问自己：

1. **跨机器不变吗？** —— 换台手机、换分辨率还成立？**只记坐标的一律不合格**（分辨率不同坐标就漂了）。
2. **换个 App 还用得上吗？** —— 只在特定 App 成立的，说明它是 L3 的典型，可以写，但要说清"这是**某类 App 的通病**"，别写成孤立的"这个页面要注意"。
3. **下一个人读了能少踩一次坑吗？** —— 有没有可执行的动作？

### 三种典型"不合格"，对照自查

| 不合格长什么样 | 问题 | 改法 |
|---|---|---|
| 只记坐标 `A: x136 y1057` | 机器相关，会漂 | 只记"点字母列、x 固定、y 依次排开"这种**结构**，坐标现场 probe |
| 只记流水账「这页有 15 道题」 | 这是页面内容，不是经验 | 改成"**点选项后自动跳下一题，无「下一题」按钮**"这种交互规律 |
| 只写「注意检查」「小心点错」 | 没有可执行动作 | 写成"**点完必须 `wait_ui.py -t "11/15"` 等推进，不能 sleep**" |

**合格的写法 = 现象 → 原因 → 做法**，三样齐全。缺一样都不算能让人少踩坑。

## 4. 写完怎么验（不许拍脑袋写）

写完**立刻**用现有脚本当场核对，跑通了才算数：

```bash
python3 scripts/probe.py                      # 验"这页读得到/读不到"、交互规律对不对
python3 scripts/wait_ui.py -t "关键词"         # 验"点完会跳到哪"这个规律是不是真的
python3 scripts/pixels.py shot.png --dots     # 验位置/色块类结论
```

- 写了坐标 → 现场 probe 实测一次；
- 写了"读得到/读不到" → 现场 dump 一次；
- 写了"点完自动跳" → 真点一次，用 wait_ui 确认它跳了。

**写的时候没验过的经验，跟没写一样。**

---

## 5. 怎么维护（不维护等于没写）

文件头两行元信息不能省：

```
updated: YYYY-MM-DD
status: ok        # ok | stale
```

- **超过 90 天没复核** → 在 index 里标记为 `stale`，别人读之前**先用脚本实跑验证一遍**，别直接照着做；
- **失效了别删** —— 改成 `status: stale` 并写清"为什么失效了（改版怎么变的）"。**"从 A 版到 B 版改了什么"比删掉有价值得多**；
- **按经验失败时** —— 先回退通用流程保证任务完成，再把失败原因补进那个文件并更新 `updated`，这是经验唯一的生长方式。
